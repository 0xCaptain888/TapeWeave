## 一、结论：先纠正参赛前提

**TapeOut 不是此处“做完一个产品／流片交付”的泛称，而是一个具有处理器、电路、晶体管、只读求值等机制的具体协议。活动是 Build X Series 下的「X Layer TapeOut Accelerate／X Layer TapeOut 开发者加速计划」。** 官方正文也称它为 hackathon，报名表另用「OKX Xccelerate」名称。因此“不应当作普通自由命题黑客松”是正确纠偏，但也不应反过来说官方没有将其称为黑客松。[S1–S3]

最重要的五个决策事实：

1. **必须围绕 TapeOut 生态、结合 X Layer。** 仅有普通 AI Agent、x402 支付或 X Layer 部署，不足以自动符合这一期要求。[S1、S2]
2. 方向开放，但平台有约束：应用、游戏、网络服务、开发工具、电路设计、PoD 机制创作均可；不要求全部逻辑放入电路，也不要求自行部署处理器。[S1、S2、S5]
3. 官方更关注**真实用户价值、商业潜力、创新、有效生态集成、完整体验**，不是只看复杂电路、Token 发行或交易笔数。[S1、S2]
4. 已有项目可以参赛，但必须有活动期间的实质新增开发，**只评新增部分**。不能直接换 README、换品牌、换链就声称完成新作品。[S1、S2]
5. 目前公开奖金池为 **100,000 USDT**，奖金是资格核验后随项目成长**分阶段发放**，具体里程碑和付款条款另议，不是“一获奖立即全额到账”。[S1、S2]

**明确推荐：做「TapeGuard——可复用、可独立复算的 Agent 支出策略电路」**，以用户已有 `agent-control-plane` 的策略、权限与回执为底座，新增真正运行在 X Layer TapeOut 上的小型确定性策略电路与验证体验。定位不是“又一个通用 Agent 平台”，而是“任何 Agent／开发者都能引用的公开策略计算组件”。第二选择是电路反例与回归测试工具；不建议优先搬运 Genesis 的完整 DeFi Hook 系统。

## 四、TapeOut 到底是什么：名称、协议与边界

### 4.1 名称的项目内含义

白皮书不是只借用芯片词汇命名，而是明确说明一套操作：[S7，第 1–4 页]

1. 协议把 NAND（与非门）元件称为“晶体管”，以 ERC-1155 Token 表示；还引入保存一位状态的 LATCH。
2. 在处理器画布连接元件，浏览器中先试算。
3. 点击“流片”：按白皮书描述销毁晶体管 Token，生成 ERC-721 电路 NFT，把连接逻辑作为链上数据保存。
4. 已有电路可当黑盒继续组合；工厂用于部署处理器。

白皮书第 3 页直接解释：“这个词来自真实的半导体产业，设计送进晶圆厂，被蚀刻进硅片。”**所以本活动中的 TapeOut 是具体协议品牌，其“流片”也是协议内的电路铸造／固化过程，不是要求提交真实半导体芯片，也不是泛指项目完成。**[S7]

### 4.2 不应照单全收的协议宣传

白皮书称电路可以永久使用、无需钱包进行免费只读求值、不能任意写状态／外部调用，并宣称工厂放弃权限、陌生电路安全等。[S7]

这些是**协议设计自述，而不是本次独立审计结论**：

- “免费”主要指只读 RPC 求值没有用户链上交易费，不代表 RPC、索引、前端、流片、存储和交易全部零成本，也不意味着可无限计算。
- 合约内部调用仍受 gas／计算资源限制；大电路可能不适合放入 DeFi 热路径。
- 只读确定性计算不等于输入真实，电路不能自行证明链外 Agent 真交付、价格预言机正确、用户授权有效。
- 永久性依赖链、节点和合约实际状态；网页／网关仍有可用性风险。
- 白皮书描述 BNB 的时钟与“巨兽”CPU，不能直接套用为 X Layer 的当前出块或处理器性能。

### 4.3 当前生态可确认到哪一步

| 能力 | 证据 | 可据此做的判断 | 不能据此承诺 |
|---|---|---|---|
| 电路／处理器／晶体管 | 白皮书和协议客户端 | 电路设计、组合、求值是协议核心 | 所有链版本 ABI 和权限完全一致 |
| X Layer 接入 | 活动规则；客户端有 chain 196、X Layer RPC 和 factory 配置 | 不是只能在 BNB 上做 | 客户端显示地址就等于已审计或最终比赛指定地址 |
| DeWEB 等生态项目 | 官方规则列名 | 可选择性集成，不强制堆叠全部工具 | SDK 接口、价格、配额、收入分成已确定 |
| 电路容器 | 客户端 UI 描述存储前端、绑定 DNS、持有资产／收付款，且有链限制 | 可作为后续托管与产品入口的验证方向 | 所有链、所有电路均支持同样功能 |
| PoD | 活动允许；客户端存在题库、反例审查、榜位与挖矿界面 | 存在设计与正确性竞争机制可研究 | 挖矿收益确定，或协议榜位等于赛事获奖 |

| `genesis-protocol` | Solidity Hook 模块、流动性保护阈值、前端与部署结构；README 自述 X Layer 经验 | Uniswap V4 和 AI 策略不是 TapeOut；热路径 gas、状态／预言机和资金安全使改造成本偏大 | 中低 |
| `scout-agent` | README 自述 Agent 服务、支付与 receipt 产品经验；文件树有前端、索引器和合约 | **源代码存在足球预测／排名系统遗留，不能只按 README 认定是干净的服务市场底座**；需先分支与模块盘点 | 低至中 |
| `meme-autopsy` | README 自述风险证据图谱、报告、闸门拒绝和 API／MCP | 主场景为 BNB meme 风险，不是 TapeOut；若只接数据装饰，生态价值弱 | 低 |

### 5.2 源文件级结论：不是泛泛“已有代码能复用”

**A. `agent-control-plane` 最适配，但要重做数值边界。**[G1]

- `packages/policy-engine/src/index.ts` 的 `evaluatePolicy` 已有 allowedKinds／allowedTargets／allowedTools、单笔和日限额、委托过期、超额审批，输出 approved／rejected／requires_approval。适合抽出有限的比较与组合逻辑。
- 其金额通过 JavaScript `Number` 比较，不宜原样转成链上资金安全条件。应新增固定小数单位整数、溢出／越界拒绝、明确位宽和规范化输入。
- `packages/session-policy/src/index.ts` 已有 principal、Agent、资产、撤销和有效期检查；但部分有效期与资产字段依赖输入，不能把链外传入的标志当已被电路证明的事实。
- `packages/receipts/src/index.ts` 已有 Merkle 构造／验证和内存 ReceiptStore。**叶子只覆盖 receiptId、actionId、intentHash、status、payment、proof，未覆盖所有 policy、reason、verification 等字段**；若新产品宣称策略结果完整防篡改，需新增完整规范化承诺，不能仅复用现成 Merkle UI 就声称全部字段受保护。

**B. `relaybond-okx` 可复用恢复叙事，不能把 verifier 消失掉。**[G2]

`contracts/RecoveryBondVaultV2.sol` 用 EIP-712 绑定主备服务、请求、失败与恢复回执、金额、期限、nonce，经 immutable verifier 签名后扣主服务押金并支付备援。TapeOut 适合做其中已给定事实的资格／额度函数；事实来源、签名、真实交付和资金转账仍需另外信任与控制。本次只读查看，不给该合约作安全背书。

**C. `genesis-protocol` 的适配更像新子产品，而不是直接迁移。**[G3]

`contracts/src/modules/LiquidityShieldModule.sol` 存在 poolDepth、区块累计冲击、stale threshold 等可变状态。可以抽取阈值比较电路，但外部数据和块内状态仍在 Solidity／Agent；将电路接入 beforeSwap 热路径必须先测 gas 和失败模式。若只是把同样计算换成更昂贵调用，未必能增加评审中的用户价值。

**D. `scout-agent` 存在可见的叙事／代码混杂。**[G4]

`apps/web/lib/contracts.ts` 仍声明 X Layer Testnet 195，并列出 PredictionMarket、MatchOracle、WorldCupPrizePool、RankingBoard 等足球预测相关地址与 ABI。这不否定 README 描述的其他新增能力，但说明不能直接把整个 main 当成纯付费情报产品，更不能沿用旧测试网地址充当 TapeOut 集成。

**E. 校准项目适合借方法。**[G5]

`test/protocol.test.ts` 包含“证据不匹配冻结”“可信 passport 发有界一次性 permit”等测试，适合借鉴负向案例和回执展示。存在测试文件不等于本次已运行通过，也不等于链上机制已经独立验证。

**复用原则：** 保留接口、产品流程、测试思路、可审计证据展示；重做真正 TapeOut 核心与数值／信任边界。代码署名、许可证和素材授权要逐项核实；不能把六个仓库一律当同一许可，或把历史部署当本期新增。

## 六、三个针对性方案与排序（初版，最新排序见补充报告）

### 6.1 评价方法（研究者自定，不是官方权重）

各项 1–5 分，5 最佳；权重为规则匹配 30%、原创性 20%、可实现性 20%、演示 15%、夺奖潜力 15%。夺奖潜力仅表示与公开评审维度的相对贴合，**未知参赛阵容与评委偏好，不能转化成获奖概率**。

| 排名／方案 | 匹配 | 原创 | 可实现 | 演示 | 夺奖潜力 | 加权分 |
|---|---:|---:|---:|---:|---:|---:|
| 1. TapeGuard：Agent 支出策略电路与独立验证 | 5 | 4 | 4 | 5 | 4 | **4.45/5** |
| 2. CircuitLens：电路反例、回归与兼容性工作台 | 5 | 3 | 4 | 4 | 4 | **4.10/5** |
| 3. RelayCircuit：服务恢复资格与额度电路 | 4 | 4 | 3 | 5 | 3 | **3.80/5** |

### 6.2 第一名：TapeGuard——策略可以复用，判定可以独立复算

**一句话：** 让 Agent 服务开发者把支出策略发布成 X Layer TapeOut 电路，用户可在不信任服务后端的情况下，用公开地址、电路 ID 和同一输入独立复算“允许／拒绝／需审批”。【建议】

- **目标用户：** 付费 API／Agent 服务商、Agent 钱包集成者、小团队开发者。首批从 3–5 个真实开发团队验证需求，先做集成服务，不假设已有付费客户。
- **首个窄场景：** 一次 API 采购的单笔上限、剩余预算、scope 有效标记和审批标记。金额用有界整数，输出 verdict 和 reason bitmask。
- **TapeOut 必要性：** 新开发的公开可组合确定性判定电路，不只是前端挂标志；外部用户能脱离平台复算并在其他应用中复用。相比纯 TS，价值在公开可引用与稳定语义，而不是声称门电路天然更安全或更便宜。
- **复用：** G1 的 action／policy 结构、session 工作流、receipt 展示；不把旧策略引擎本身算新成果。
- **真正新增：** 固定输入规范、门级策略电路、X Layer 发布／查询适配器、差分测试、带 chainId／处理器／电路 ID／输入承诺／区块信息的回执、独立验证页和 SDK 示例。
- **边界：** 电路负责计算，不能保管密钥、阻止绕开它的签名者，不能自行证实链外授权标记。MVP 如只有链外执行器强制检查，应如实叫“策略计算与验证层”，不叫“不可绕过的链上保险箱”。
- **收费：** 托管索引、团队策略版本管理、审计导出和接入服务；免费公开求值仍可用，不强行对开放电路求值本身收通行费。建议先试按团队订阅或一次性集成费，价格待用户访谈。
- **获客：** 官方开发者社区和自有 Agent 项目提供最小 SDK／三种样例，联系真实开发者完成集成与反馈；不以刷地址、刷交易制造采用率。

**三分钟演示脚本：**

1. 0:00–0:25：展示“Agent 想买 120 单位服务，但授权只剩 100”的真实痛点。
2. 0:25–1:00：正常请求允许，超额拒绝，临界值和缺审批显示原因。
3. 1:00–1:40：打开 X Layer 处理器地址与电路 ID，用第二个独立客户端复算同一结果。
4. 1:40–2:15：故意篡改输入／回执，验证器指出不一致；RPC 失败时不偷偷改用允许结果。
5. 2:15–3:00：展示另一应用复用同一电路、目标用户反馈、收费对象、新旧开发分界。

**两周 MVP 估算（非官方工期）：** 1–2 名开发者在已有工程可用、ABI 和 X Layer 处理器确认的前提下。先用 16 位小额演示单位控制电路大小，不将其误标成支持任意真实金额。后续扩位宽要测资源和溢出，不通过则保持受限产品定位。

**最大风险：** 与普通布尔策略比较器差异不足。解决方法不是加更多 Agent，而是交付独立复算、跨应用复用、规范化输入与边界测试，并获得真实用户试用。若电路发布／求值能力未确认，不能用本地模拟冒充链上。

### 6.3 第二名：CircuitLens——不是再做一个电路编辑器

**一句话：** 为 TapeOut 应用开发者提供“引用这个电路前，知道它在什么输入上会错”的反例与回归工作台。【建议】

- 输入 X Layer 处理器地址、电路 ID、预期函数与有界测试域，读取真实电路，执行真值表／差分测试，输出最小反例、版本对比和可复现报告。
- 小位宽可穷举；大输入域只做有预算测试，明确覆盖率，**不把 fuzz 通过说成形式化证明**。
- 复用 G1 的证据结构、G5 的负向测试方法；新增电路读取／求值适配、参考模型、反例最小化、CI 报告和链上身份绑定。
- 目标客户为电路作者和应用集成团队；开源本地测试，托管 CI、团队回归历史和批量报告收费。
- 演示“两个看似相同的加法／额度电路，一个在边界溢出；系统定位反例并给修复前后对比”，可视化效果清楚，资产风险低。
- **竞争风险：** 协议客户端已经存在反例审查和 CE Bot 描述。[S8] 必须差异化为“应用集成前的回归与兼容性 CI”，不能声称首次发明反例挑战。是否与官方现有工具重叠需访谈核实。
- 建议不自动提交 kick／挑战交易，默认只读报告；是否参与链上机制另行授权并核验规则。

### 6.4 第三名：RelayCircuit——让服务恢复规则公开计算

**一句话：** 对已经由可信验证方确认的服务失败与备援交付，用 TapeOut 电路计算恢复资格、额度和拒绝原因。【建议】

- 复用 G2 的主服务失败→备援完成→证据绑定流程，新增公开资格电路和复算界面；先用无资金演示或明确标注模拟资产。
- 输入失败已核验、备援独立、额度、可用押金、期限等确定事实；输出资格和恢复上限。签名验证、抗重放、时间真实性、转账和真实交付仍在电路外／其他合约。
- 收费对象为付费 API／Agent 服务商，按恢复运营服务或订阅收费；不包装成无风险保险，不承诺赔付收益。
- 演示效果强，但业务链条长、verifier 信任难隐藏，资金融合需要额外审计；新增电路若只做一次简单比较，容易被认为装饰性集成。
- 因此列第三；更适合作为 TapeGuard 完成后的第二个集成客户，而非首发就做完整押金金融系统。

## 七、明确推荐与执行门槛（初版 TapeGuard 路线，非最新首选）

### 7.1 为什么选择 TapeGuard

【判断】它同时具备：用户已有可拆分的策略代码、无需外部价格预言机的确定性小内核、直观失败案例、公开电路的复用意义、可解释的收费对象。相比 CircuitLens，商业产品故事更完整；相比 RelayCircuit 和 Genesis，避免首先处理押金结算或 DeFi 热路径。

不推荐以下伪适配：

- 给旧 Agent 加 TapeOut Logo、钱包连接或 BEM 行情面板；
- 只部署在 X Layer，但根本没有 TapeOut 使用证据；
- 把 LLM 推理称为电路执行，或把 TS 回放伪装成链上结果；
- 用 PoD 挖矿收益替代用户价值和收入模式；
- 只搬旧网站到 DeWEB 就忽略规则文本差异；
- 复用旧仓库交易数作为本期新增完成度。

### 7.2 开发前 48 小时：必须验证，不需要先投入资金

1. 从官方技术支持获取当前 X Layer 处理器、合约版本、ABI、求值方法、输入位宽／门数／资源限制、流片费用和权限状态。客户端地址只能作线索。
2. 对一个已知最小电路做两种独立只读查询，固定区块或证明上下文，确认结果一致和链 ID 正确。链外序列化与端序也要有测试。
3. 本地构建最小策略参考函数，穷举小位宽输入，测结果、边界和溢出。没有部署授权就止于本地设计和只读验证。
4. 与潜在用户验证“公开可复算的规则”是否比普通 SDK 更有价值；记录真实反馈，不假装合作或已有付费。
5. 询问规则差异与现场要求：纯 DeWEB 是否可单独达标、线下强制程度、差旅与签证、奖款里程碑。用官方群回答更新参赛计划，不把本报告猜测当答复。

**继续条件：** 真实 X Layer TapeOut 求值可用；小内核电路资源可接受；至少有潜在集成者认可复算／复用价值。若没有可接受的可验证接口，应先停止承诺 TapeGuard 交付；可在电路读取可用时转 CircuitLens，但不能仅为“参赛”硬凑包装。
