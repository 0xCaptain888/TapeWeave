# TapeOut 构建兼容深挖：真实浏览器对照与独立立项反证

> 访问／实验日期：2026-10-17，America/Los_Angeles。承接[扩围复筛](tapeout-demand-rescreen-2026-10-17.md)。本轮只读获取资料并运行自编本地夹具，无账号登录、外部联系、钱包、写链或部署。**尚未找到满足用户全部门槛的大奖选题；本轮没有把构建兼容升级为产品推荐。**

## 一、这轮回答了什么

上轮把构建兼容与运行差异放在取证第一位。这轮不先写新方案，而是验证三件事：

1. 固定 TapeKit 网关究竟允许什么脚本执行？
2. 可见差异是否已经被官方测试覆盖？
3. 公开 TapeNow 仓库是否足以判断它缺少发布检查？

**结果：**本地 Chrome 确认策略会阻止跨源脚本，而同源脚本、同源模块、blob、内联与eval可以执行；错误MIME加nosniff在普通网页对照中也失败。上游已有跨源脚本与动态导入拦截测试。TapeNow明确不公开工作台实现，无法据公开工具树判断它缺哪项检查。因此，“做一个迁移扫描器”仍无充分独特价值，不能推荐完整开发。

## 二、固定源码与文档：三个不能混淆的环境

### 2.1 TapeKit 网关的实际响应策略

读取并经GitHub内容API重新核对 TapeKit 提交 `40994bd65baedbda4df72cb0985031a5f082f606` 的 `sw-gateway/serve.js`，与前轮下载文本一致。[S1]

- `SITE_CSP` 中 `script-src 'self' 'unsafe-inline' 'unsafe-eval' blob:`，允许同源、内联、eval与blob脚本，没有放行普通链外脚本地址。
- `style-src`、图片、字体、媒体允许https；`connect-src`允许https与wss；不能笼统称“不能访问外网”。
- `fileResponse` 使用文件声明的MIME加charset，附带 `x-content-type-options: nosniff` 和同一份CSP。错MIME可能导致浏览器拒绝脚本，但本轮没有证明真实发布器会产生错MIME。
- 此文件由自验档和兼容档共用，是固定源码事实；不证明今天所有网关实例的部署版本相同，也不覆盖所有其他客户端。

### 2.2 社区指南不能替代所有运行环境的策略

社区指南固定提交 `64c8a115a407d4fa9561fecb4ab768b7b9e0eed9` 的外部脚本章节描述了独立frame、`default-src 'none'` 与内联／blob脚本。[S2] 它可能针对特定预览器／版本，**与上述TapeKit网关的策略文本不同**。本轮未运行该指南所述环境，不能宣布它错误，更不能将其描述推广为全TapeOut。

因此，兼容研究必须标注：客户端、模式、版本、响应头、实际请求及执行结果。只列“DeWEB兼容／不兼容”会掩盖环境差异。

### 2.3 TapeNow不是仅由公开SDK构成的产品

固定 TapeNow 提交 `ca5afda2ee6ecff578d4657503e7d2c2a28c478c` README明确：公开仓库是验签工具、SDK、规范、文档和测试；**工作台网页、API、Cloudflare Worker目前不开源**。[S3]

更新日志已经声明：发布检查、固定文件和配置、数据兼容性检查、外部依赖清单、真实浏览器可访问确认、固定Gateway、交易重试等。[S4] 这些是作者对功能的陈述，本轮没有登录独立体验，不能把每一项当作验证通过；同样也不能因为仓库里没找到checker就写“产品没有checker”。

本轮直接用Python重新请求官方手册返回HTTP错误，未取得新版本；不据此判断手册或服务宕机。上轮取得的官方手册仍仅作为当时文档观察，不能冒充本轮实测。

## 三、本轮新实验：同一内容，只改变CSP

脚本：[research/tapespec/build_compatibility_probe.mjs](../research/tapespec/build_compatibility_probe.mjs)。运行：

```bash
node research/tapespec/build_compatibility_probe.mjs
```

- Chrome：`155.0.8059.84`；Node内置HTTP与进程API，无npm依赖。
- 两个 `127.0.0.1` 随机端口，其中第二端口作为跨源脚本端点。它是本地HTTP跨源对照，不是互联网HTTPS CDN；本轮没有测试真实CDN、CORS组合或全部浏览器差异。
- 同一页面分别无CSP与原样 `SITE_CSP`；表达式和固定上游逐字比较一致，保留MIT声明并复用已有许可证文件。
- 七项行为分别观察，两种策略共14个行为结果；附加断言核对跨源端点请求数与CSP违规事件。这里不是14个真实应用，也不是14种客户故障。

| 行为 | 普通无CSP对照 | 固定TapeKit策略夹具 | 能得出的结论 |
|---|---|---|---|
| 内联脚本 | 执行 | 执行 | 该策略不是禁止一切内联 |
| eval | 执行 | 执行 | eval本身未被该策略禁用；不代表所有动态执行方案安全 |
| 同源经典JS | 执行 | 执行 | 相对路径可执行是一个最小对照，不代表所有打包产物可运行 |
| 同源ES module | 执行 | 执行 | 不能笼统说ES module不兼容 |
| blob脚本 | 执行 | 执行 | 该策略允许此种本地构造的blob脚本 |
| 跨源JS | 执行，端点收到1次请求 | 拦截，端点0次请求且出现script-src-elem违规 | 策略确实能解释这类迁移差异，但并非新缺口 |
| text/plain脚本＋nosniff | 不执行 | 不执行 | 此失败不是TapeOut特有，不应拿来制造独特需求 |

输出证据标签为 `real-chrome-local-policy-fixture-only`。页面、脚本、路由、MIME样本均为自造；只有CSP表达式来自固定上游。**未运行TapeNow发布检查、TapeKit内核、SW或RPC，未校验真实链上字节／哈希／身份，未在X Layer上运行应用。**

Chrome使用临时配置，禁用扩展和后台网络，结束清理服务和配置；未抓包，因此不承诺Chrome绝无后台联网。夹具不改变安全策略来绕过真实网关，也不建议让用户禁用安全保护。

## 四、主动找反证：上游已经测试过最明显的差异

同一TapeKit提交的 `sw-gateway/test/e2e.mjs` 已有：[S5]

- 链外fetch、图片与WebSocket放行；
- CDN经典脚本被拦；
- 跨源 `import()` 被拦；
- 状态页记录链外访问和被拦脚本；
- srcdoc／沙盒／blob／data子框架的相关防绕过检查。

**本轮只读这些测试，没有执行上游E2E。**它们足以反驳“生态连链外脚本兼容测试都没有”的叙事；不能证明所有构建产物都已覆盖，也不能据此认定任何线上安全性质。

此外，TapeNow更新日志0.9.14明确说：删除旧路径延后到新文件与入口写完之后，缩短缺文件窗口，但仍逐笔原地更新、交易全部确认前可能新旧混合。[S4] 这进一步支持“发布中间状态是已被作者识别的限制”，**不是第二个独立客户，也不是会话漂移的独立需求证明**。它没有自动让TapeSpec获得独特优势。

## 六、下一轮需要拿到的硬证据

1. 一个**真实、可合法获取的构建产物**与可重复的失败，而不是继续自造样本；记录原有检查究竟报告了什么，不凭缺源码推断。
2. 说明失败影响和维护成本，核对是否已经解决。单一CSP报错、缺index.html或CDN引用若现有提示即可解决，应结束独立工具叙事。
3. 若本地重现只需一条现有规则，应贡献已有工具；只有跨团队反复出现、现有检查确实漏掉、行为差分能稳定阻止回归时，才重新评估独立工具。
4. 未获授权不登录用户账号、联系维护者、运行不可信项目安装脚本、付费或发布。需要这些证据时明确记录获取条件，不虚构确认。

本轮有实际实验进展，但仍未找到“常见重要需求＋独特核心竞争力”同时成立的新选题。继续研究应寻找真实失败与独立采用，不再先扩充产品形态。
