# TapeWeave V1 本地参考接入指南

日期：2026-10-17。本文是本项目参考包的应用约定，不是官方TapeOut标准、SDK或安全认证。不联网、不连接钱包、不制造或消费链上电路。外部协议事实及固定来源见[研究入口](../../docs/tapeout-final-research-decision-2026-10-17.md)；本文未重新获取外部资料。

## 1. 先确认接入的是什么

- [reference-bundle-v1.json](reference-bundle-v1.json)：两枚固定本地网表、16条转换、64份系统最优回放；不是玩家成绩。
- [export_reference_bundle.py](export_reference_bundle.py)：生成及一致性检查；运行 `python3 research/tapeweave/export_reference_bundle.py --check`（仓库根目录）。
- [behavior_replacement_probe.py](behavior_replacement_probe.py)：有限字节解释器及早期Host实验。
- [strategy_sweep.py](strategy_sweep.py)：本包使用的四回合策略模型。

**不要混用模型：**早期Host依据progress补能；本包固定回合0、2补能。花园在本包按上一回合请求产生本回合到期效果，不是早期Host的即时进度封顶。所有挑战初态为0，四回合，窗口预先可知，trigger无成本。

`chain_identity`为null。摘要只识别字节，不证明制造、所有权、版权、执行权限或安全。当前没有外部接入者，也没有实测接入耗时。

## 2. 接入分层：不要按卡名重写行为

| 层 | 输入／责任 | 不应该做什么 |
|---|---|---|
| 装载 | 只接受包内固定制品，核对hex与摘要、档案和版本 | 不因SHA-256匹配就信任任意上传；不能把摘要当授权 |
| 输入 | trigger为玩家0/1选择，recharge由宿主回合生成；打包为`trigger | (recharge << 1)` | 不允许玩家直接声明补能事实；不把字符串或浮点数悄悄转整数 |
| 求值 | 传入旧状态与打包输入，返回`next_state, request` | 不按pulse／alternating分支替换成专用公式；普通对照另计 |
| 业务效果 | 训练消费当前request；花园消费上回合pending；有效分为到期效果×当前窗口 | 不把request直接当奖励、余额或权限凭证 |
| 提交 | 验证全部结果后，一次更新状态、pending、回合、得分与日志 | 不在求值失败后推进回合；不在回放时再次发效果 |

宿主可以有训练／花园业务分支，但不应为每张卡增加执行分支。两张卡通过同一求值入口运行；实际效果由宿主规则决定。调用现有解释器是本地参考接入，不是独立解释器验证。

## 3. 单回合处理顺序

以下为待接入实现遵守的逻辑顺序，不是已完成的持久化／并发安全实现：

1. 校验挑战未结束、回合匹配、制品属于固定集合、状态及trigger严格为0或1。生产实现应明确拒绝布尔值以外的隐式类型转换，不能依赖Python中`True == 1`的宽松相等。
2. 从当前回合生成recharge，保留old_state和old_pending快照。
3. 调用有限解释器。检查返回状态、请求均为0或1；任何异常作为求值失败，不换成公式后仍记成功。
4. training的effect_due取request；garden取old_pending。计算`gained = effect_due * window[turn]`。花园本回合request留待下回合，最后回合请求不会在四回合内成熟。
5. 生成候选日志后再提交：next_state、pending=request、turn+1、累计得分。界面若使用异步调用，必须另行处理重复点击与旧响应；本参考包未解决这些问题。
6. 回放只读日志；新挑战状态和pending均重置为0。换卡只能开启新挑战，不能继承旧卡状态。

## 4. 用固定样例核对位序与时序

先遍历每张卡的全部8条转换，不只核对输出，还核对下一状态。

| 卡／旧状态／输入 | 应得(next_state, request) | 解释 |
|---|---|---|
| pulse／0／trigger=1,recharge=1 | (1,0) | 本拍补能不立即请求，输出使用旧状态 |
| pulse／1／trigger=1,recharge=0 | (0,1) | 消耗旧蓄能并请求 |
| alternating／0／trigger=1,recharge=0 | (1,1) | 不需要补能，不符合“先蓄能”约束 |
| alternating／1／trigger=0,recharge=1 | (1,0) | 无trigger不翻转，忽略recharge |

再用包内每个`optimal_reference`的actions逐拍求值，比较全部trace字段。先使用包内动作以隔离求值／计分错误，之后才让玩家自由选择动作。不得拿任意玩家动作与系统最优分比较后认定执行错误。

## 5. 失败处理验收表（尚待接入实现执行）

以下是测试要求和预期结果，不是新通过的测试记录：

| 输入／操作 | 预期 |
|---|---|
| 未知制品或摘要不符 | 装载失败，不进入挑战；不可静默选另一张卡 |
| trigger=-1、2、字符串，或状态越界 | 显式拒绝；不改变回合、状态、pending或得分 |
| 截断网表或解释器异常 | 显示求值失败，不提交任何效果；保留退出入口 |
| 同一回合重复提交 | 仅一次成功；需由接入者实现去重，不靠UI禁用充当保证 |
| 挑战中换卡 | 拒绝；可以显式结束后开启新挑战 |
| 花园回放／刷新日志 | 不重新成熟或计分；刷新恢复尚未实现时必须明确提示 |
| 另一个宿主或实例执行 | 不修改当前实例状态；不能共享pending |
| 未来真实执行上下文变化 | 与本地模式分开处理，不自动视为已验证同一语义 |

已存在的8项ReplacementTests仅覆盖早期本地Host的部分边界，不证明此表在新界面、策略宿主、异步请求或持久存储下全部通过。接入实现须自己运行、保存结果和失败原因。

### 5.1 后续：同步内存策略引擎的有限补证（2026-10-17）

新增 [test-host-boundaries.mjs](demo/test-host-boundaries.mjs)，在仓库根目录运行 `node research/tapeweave/demo/test-host-boundaries.mjs`。作者本地执行通过60次拒绝调用的输入不变断言，以及两模式的宿主隔离、花园延迟与零态重置检查。这不是上表全部通过，也不是独立接入。

检查发现 `demo/engine.mjs` 的普通公式路径此前会隐式转换字符串／布尔动作，且未知宿主会被当作花园；现已在共同入口拒绝非整数位动作与状态、非法四位窗口、未知宿主／卡片模式／执行方式及越界分数。求值异常在返回候选状态之前抛出，不修改传入对象。正常路径在字节和普通模式均保留相同规则。

**补充失败恢复检查：**随后扩展为66次拒绝调用及4组局中失败／重试检查（两模式×两宿主）。在动作001后冻结状态、日志、卡片和窗口：训练已有1分，花园为0分，两者均有pending=1。非法动作被拒绝，字节模式另检查截断网表求值失败；随后合法重试与无失败的对照结果一致，旧局保持不变。最终训练2分、花园1分。这只证明该纯函数调用不写入被冻结对象，并不提供真实提交或重试去重。

测试编写时曾把动作011后的pending误预期为1，实际为0而断言失败；已改用001来构造待生效请求，并分别记录花园延迟分数，没有为迁就测试修改业务规则。

**历史日志所有权修复：**新增4组两模式×两宿主的候选分支测试。测试先复现：原实现仅复制trace数组，历史行对象仍与旧局和其他候选共享；修改新候选的历史request会污染旧局。`advance`现用`structuredClone`复制已有trace后追加新行，测试覆盖新候选修改不影响旧局／另一候选，以及旧局修改不影响另一候选。既有66次拒绝、4组冻结恢复及完整回归仍通过。本修复限于本地日志对象所有权，不校验历史真实性或阻止调用方篡改自己持有的结果。运行环境需支持`structuredClone`（本轮Node与Chrome已验证，其他浏览器未验证）。

**未覆盖：**入口不重新校验历史trace的一致性、不校验完整卡片白名单／SHA（装载层负责）；直接用不同卡片调用仍不构成局中换卡防护。`advance`是纯候选计算：同一旧状态调用两次会得到两个候选，不提供去重或提交事务。异步旧响应、并发、持久恢复、钱包、链消费和真实宿主仍未实现；不得把这60次拒绝称为60个真实故障或安全认证。

## 6. 公平普通对照与接入记录

普通对照可使用相同卡说明、共享接口、制品标识、日志和状态隔离，允许版本化函数库或共享合约；不要故意让它逐卡修改消费代码。分别记录装载、核对、映射、错误恢复所花的时间、获得的帮助、改动文件、专用分支及失败原因；目前没有这些数据。

本项目作者按此指南接入，只能称作者自测。非原作者开发者的结果也应说明关联关系；独立接入不自动等于持续采用。若两种实现同样顺利，而电路表示没有可描述收益，必须保留反证。

## 7. 到哪里停止

本指南不包含钱包认证、制造交易、gas预算、链上宿主原子提交、升级权限控制或任意REF支持。没有这些能力时不声称已经满足参赛集成要求。后续外联、招募、部署、写链和付费均需另行授权。先核对有限制品与固定任务，不扩大成通用安全装载器。
