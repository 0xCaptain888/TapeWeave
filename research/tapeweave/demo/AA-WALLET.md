# AA 网页、实际插件与 Android 验收

更新：2026-10-26。网页适配器与人工记录工具已实现；实际插件兼容、真实签名及 Android 真机通过必须另有实际结果，作者替身测试不替代这些结果。

## 选择入口与兼容性

- `native.html`：已部署合约账户，钱包实际支持 EIP-5792 2.0.0 的 `wallet_getCapabilities`、`wallet_sendCalls`、`wallet_getCallsStatus`。
- `chain.html`：普通 EOA 插件钱包；连接到 AA／委托账户时不通过此路径发送。
- `device-check.html`：选择普通插件、AA 或 Android，逐项填写真实观察并导出 JSON。

三页均可从主网页导航进入。只在自己控制的钱包内确认，不向页面提供助记词、私钥、API Key 或签名服务凭据。

AA 页仅针对 X Layer 主网196、固定宿主 `0x440c3CC7DdD50566126754199Df7336499eE1E20` 和 EntryPoint v0.7 `0x0000000071727de22e5e9d8baf0edac6f37da032`。钱包须明确返回本链 `atomic.status = supported`；`ready` 不会触发账户升级，不支持时不会暗中改用普通转账。拒绝未部署账户、EOA 和 EIP-7702 委托代码。任意批量、其他 EntryPoint 和钱包专有 AA 协议不在当前支持范围。

**OKX 官方工具账户、OKX 插件中的普通账户及插件暴露的智能账户不一定相同。** 钱包名称不能证明支持 AA。连接时实际请求账户、网络、能力及已部署代码，不发送交易。不支持的插件须使用官方 AA 工具，或用普通 EOA 打开普通入口，不能改 RPC 返回值来通过真实验收。

接口依据：[EIP-5792](https://eips.ethereum.org/EIPS/eip-5792)。应用生成随机请求 ID，发送前保存并要求钱包原样返回；不兼容时保留意图供人工恢复，不自动降级协议或重复提交。

## 实际 AA 操作

连接失败时先点击“只读检测连接问题”，再复制诊断报告返回。本功能只读取已授权账户、网络、代码与能力，不请求连接授权、签名或交易，也不上传。报告区分未检测到插件、未授权、网络错误、普通／未部署账户、委托账户、能力不支持与需要升级。显示可预览不等于真实插件验收通过；账户／网络切换后旧诊断清空。

1. 在已安装钱包的浏览器打开 `native.html`，选择实际插件并连接，核对账户、网络及钱包版本。能力拒绝时保留错误，记录失败或未完成。
2. 选择蓄能卡，点“模拟并预览新局”。这是固定宿主内部调用的 `eth_call`，**不是完整 UserOperation 签名前模拟**，页面没有取得最终总费用。
3. 阅读费用提示并勾选，再点“确认并打开 AA 钱包”。在钱包实际界面检查账户、网络、目标、零价值调用、gas 和赞助；费用是否为零由钱包决定。
4. 首次在钱包拒绝一次，确认页面提示拒绝且不重试。拒绝以外的异常属于结果不明，不能用重发来测试。
5. 重新预览并明确确认一次。页面先保存意图，再调用 `wallet_sendCalls`，每次仅一条固定宿主调用。可能发生主网 gas 费用，最终确认由钱包持有人完成。
6. 点“向原钱包查询请求状态”。钱包状态仅提供候选交易哈希；页面另外读取公共 RPC 回执、规范区块、完整宿主代码与会话，核对成功 UOP 的 sender、EntryPoint 和宿主事件区间。
7. 点“核验已绑定的 AA 回执”。至少两块深度、事件和状态通过后先写本机历史，再清除待处理意图。不会重新验证完整 UOP 签名，单 RPC 不是独立提供商共识或最终性证明。
8. 开局后逐笔“等待→等待→触发→触发”，每次重新预览、勾选、钱包确认、查询和核验；不自动签名。蓄能应训练2、门1、余钥匙1；交替应训练1、门0、余钥匙2。
9. 导出 AA 回执，在验收页选择 AA，记录实际钱包、被测提交、观察和真实交易哈希。填写哈希本身不触发重新验链。

若同块还有后续动作，回执明确记录 `laterActionsInBlock`；不把区块末状态冒充目标动作刚结束的瞬时状态。外层 bundler 费用与该 UOP 实付分列，不以外层交易 `from` 冒充 AA sender。

## 刷新、异常和保存

- 请求 ID 在打开钱包前写本机存储。刷新不自动连接、签名、查询或重发。
- 连接原账户手动查询 ID，或粘贴钱包中真实外层交易哈希恢复；仅接受原 AA、原操作且在发送边界后的成功交易。
- 已绑定哈希的回执核验不需要再次签名。未知、钱包终止、回滚、存储满或记录冲突均保留意图，不自动解锁发送。
- 先在钱包检查不明请求；不要清站点数据或切普通入口绕锁。失败记录没有自动删除按钮，须人工确认钱包与链状态后处理。
- 普通与 AA 共享跨页 Web Lock 并检查双方待处理意图；浏览器必须支持 Web Locks。外部钱包／站点仍可能改变会话，版本变化必须重新读链和预览。
- AA 历史独立保存，最多100条、512 Ki字符；导出严格只含公开意图和回执，不含待处理原文或任意附加字段。暂无 AA 备份导入／全链索引，清站点数据仍会丢失。

## 普通插件真实签名

在验收页选择普通插件，在 `chain.html` 执行六项：连接不签名；网络／账户核对；真实拒签；重新预览并在插件确认一笔；公开回执核验后刷新读取本机会话；有预览时切换账户，确认失效。发送通过项须附自己的新交易哈希。模拟钱包或历史官方工具交易不能代替此次插件验收。

## Android 真机

九项完整步骤见 [ANDROID-CHROME.md](ANDROID-CHROME.md)。手机 Chrome 打开公开 HTTPS 作品页和验收页，不需电脑服务。填写真实型号／Android／Chrome版本、被测 SHA，保留失败与未完成，复制 JSON 返回本任务。系统剪贴板权限拒绝和手动复制分开记录。

也可用数据线连接手机、启用 USB 调试，在自己的手机确认调试授权，然后在仓库根执行只读预检：

```sh
ADB=/Users/lyh/Library/Android/sdk/platform-tools/adb node scripts/android-preflight.mjs
```

脚本不安装、不解锁、不操作钱包、不打印设备序列号，只读设备自报系统、Chrome 和模拟器标记，不是硬件认证或九项通过。2026-10-26本机检测为 **0台就绪设备**，真机验收未执行。
